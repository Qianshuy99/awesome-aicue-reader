# 数据、配置与缓存

## 本地保存了什么

| 数据 | 存储位置 | 说明 |
| --- | --- | --- |
| 设置项 | 脚本管理器存储（`GM_setValue`） | 所有面板的偏好，随改随存 |
| 响应缓存 | IndexedDB | 帖子、楼层、用户卡片等接口响应，带新鲜度期限 |
| 会话内状态 | 页面内存 | 浏览历史、资源监控与请求日志，关闭标签页即丢失 |

阅读器不保存密码或长期凭据。写操作使用的会话与 CSRF token 来自宿主页面的启动载荷，随宿主会话生效与失效。

## 缓存的新鲜度

不同类型的数据有各自的新鲜期：用户卡片较长，通知与列表较短。命中缓存时先展示缓存内容，过期后在后台取新数据并替换。这样做的取舍是：翻回读过的楼层很快，但极短时间内的原站改动可能还没反映出来。需要立刻看到最新内容时，清理对应缓存或刷新页面。

## 备份与恢复

设置的导出、导入与重置都在[数据管理](/settings/data-management)面板。建议在两个时机导出：调整性能参数之前，以及更新脚本之前。

缓存不参与导出。它是可重建的派生数据，换设备时无需迁移。

## 清理的影响范围

![数据管理面板中按类型列出的缓存与清理入口](/screenshots/18-cache-cleanup.png)

清理缓存只删除当前浏览器里的阅读器数据。以下内容不受影响：

- 言灵工坊原站的帖子、回复、私信
- 收藏、点赞等互动记录
- 阅读器的设置项（清理缓存与重置设置是两个独立操作）

清理后首次打开帖子会明显变慢，因为所有数据都要重新取。这是预期行为。

## 体积增长

响应缓存有条目上限，超出后按新鲜度淘汰旧记录，正常使用不会无界增长。如果观察到体积持续异常增长，先全量清理一次，再在[请求数据](/settings/overview)面板观察请求类型分布，判断是否某类请求在反复取数。
