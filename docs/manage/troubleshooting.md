# 故障排查

## 入口按钮不出现

按顺序检查：

1. 当前域名是否为 `aicue.top`、`www.aicue.top`、`flarum.aicue.top` 之一。不在这三个域名时脚本会直接退出，这是设计行为。
2. 脚本管理器是否启用，脚本本体是否处于开启状态。
3. 是否有其他 userscript 或浏览器扩展改动了讨论列表结构。阅读器依赖 Flarum 的列表项结构定位入口。
4. 刷新页面。脚本在 `document-start` 注入，页面加载中途启用扩展需要刷新才生效。

## 界面出现但没有样式

样式表通过 `@resource` 从 jsDelivr 加载。CDN 不可达或被拦截时，界面会呈现无样式的裸结构。确认能访问 `cdn.jsdelivr.net`，再刷新页面。

## 内容加载不出来

1. 先确认在原站能正常打开同一个帖子。原站不可用时阅读器同样取不到数据。
2. 确认已登录。未登录时受权限保护的内容取不到，写操作会提示会话未就绪。
3. 清理响应缓存后重试，排除缓存中的坏数据。
4. 打开请求数据面板，看是否有请求持续排队或反复失败。

## 遇到限流

![请求数据面板中 429 限流状态与退避记录](/screenshots/20-troubleshooting-429.png)

请求较密时站点会返回 429。阅读器的处理方式是记录该端点的限流状态并退避，随后用探测请求确认恢复，期间新请求排队等待。这段时间界面会变慢但不会报错退出。

能做的事：

- 降低性能设置中的预取需求，减少请求总量。
- 避免同时开多个标签页做批量操作。请求账本是同源标签页共享的，多标签会共同消耗预算。
- 批量下载图片时耐心等待，不要反复重开对话框。

## 长帖卡顿

按“先需求、后渲染”的顺序调：

1. 降低主楼层预取量与楼中楼自动请求。
2. 缩小 DOM 渲染窗口。
3. 关闭默认展开楼中楼。
4. 关闭跳转闪烁与等待动画。

改完需要重新打开阅读器才生效。调整前建议先导出设置，便于回退。

## 楼层关系不对

某条回复没有归入楼中楼，通常是因为正文中缺少提及标记。Flarum 没有回复目标字段，本项目的楼层关系由提及推断。这不是可以通过清理缓存修复的问题，详见[楼层、时间轴与历史](/guide/navigation)。

## 某个按钮不见了

Boost、Reactions、Post Voting、关注、举报、指定负责人等依赖 Discourse 插件的入口在言灵工坊一律隐藏。完整清单见[回复与社区操作](/guide/community-actions)。

## 收集诊断信息

反馈问题时，附上以下内容能显著加快定位：

- 脚本版本（关于面板）与脚本管理器名称版本
- 浏览器与操作系统版本
- 复现步骤，以及问题出现在列表页还是详情页、哪种显示形态
- 请求数据面板中相关请求的状态
- 浏览器控制台中带 `[LDP]` 前缀的报错

到[仓库 issue](https://github.com/Qianshuy99/awesome-aicue-reader/issues) 提交。
